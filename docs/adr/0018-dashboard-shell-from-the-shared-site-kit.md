# ADR-0018: The dashboard shell is a vendored copy of the shared site kit

- **Date:** 2026-11-05
- **Status:** Proposed

## Context

The report dashboard ([ADR-0012](0012-static-report-dashboard.md)) copies its tokens, header, companion links and phone tab bar by hand from the sibling dashboards (decision 5, last consequence: "a palette change there is repeated here by hand"). The owner's five GitHub Pages sites (portfolio, `agent-patterns`, `autonomous-dev-loop`, `ai-dev-tools`, this dashboard) read as five separate sites: no shared top bar, no shared footer, no link from every site to every other.

`koydas/koydas` decided, in its [ADR-0001](https://github.com/koydas/koydas/blob/main/docs/adr/0001-shared-site-shell-vendored-kit.md), to distribute one shared shell (top bar with a site switcher, footer, page-header block, design tokens) as a **versioned kit, vendored into each repository** with the version and a hash it carries. This dashboard is the one site that cannot take anything at run time: its pages carry no script, no `<link>`, no `@import`, no external asset, and `dashboard.py` imports only `models` and `report` from the package (`tests/test_dashboard.py`).

## Decision

1. **The shell is a copy of the kit's `python` profile, inlined in `dashboard.py`** between `# BEGIN site-kit` and `# END site-kit`: version, hash, per-file hashes, the kit's CSS, three HTML templates and the Python renderer. It is generated by the kit's `kit.mjs sync --python`, never edited here.
2. **Static HTML and CSS only.** The site switcher and the phone menu are one `<details>`; the shell adds no script, no external asset, no dependency and no import to `dashboard.py`. A page is still a function of the report files only: the shell contains no timestamp and nothing from a report.
3. **The shell is always dark** (the kit palette); the content of the pages keeps its own light / dark theme. The dashboard's own header, tabs and phone tab bar are unchanged and sit below the bar (the header and the sticky aside are offset by `--sk-bar-h`).
4. **The overview opens with the kit's page-header block** (eyebrow, title, one line). It carries the page's `<h1>`.
5. **The links the shell adds** are the five sites' root URLs and the repository's GitHub URL, all fixed in the kit; none comes from a report. `tests/test_dashboard.py` allows exactly these URLs, not a prefix.
6. **A test fails when the block drifts** from the version and hash it declares (`tests/test_site_kit.py`). The kit's own repository checks every repo weekly for version and hash drift (a read-only workflow).

## Rationale

- Inlining keeps ADR-0012's constraints literally true: no new import (the architecture test pins the relative imports to `models` and `report`), no script, no dependency, no network at build or run time.
- A hash makes "the copy was edited by hand" a failing test instead of a review comment.
- A copy is the cost the sibling dashboards already pay (ADR-0012, ADR-021 of `ai-dev-tools`); the kit makes it one command instead of three hand edits.

## Alternatives considered

- **A runtime include of the portfolio's shell.** Rejected: it needs a script or a fetch, and ties this dashboard's availability to another site's deploy.
- **An npm package or a Python package for the kit.** Rejected: a new dependency of a package whose dashboard has none, and a release process for about a hundred lines of CSS.
- **A separate `site_kit.py` module imported by `dashboard.py`.** Rejected for now: `test_the_dashboard_module_reads_reports_only` pins the relative imports to `{models, report}`. Loosening that test is a different decision and would need its own ADR.
- **A policy of this tool for the shared shell.** See the open question.

## Consequences

- ✅ One top bar, switcher, footer and token set across the five sites; each reachable from every other in one click.
- ✅ The dashboard stays scriptless and dependency-free; the existing tests still hold (one allowlist extended to the five site URLs).
- ⚠️ `dashboard.py` grows by the generated block (about 20 KB, long lines, excluded from formatting by `# fmt: off`).
- ⚠️ The shell is dark on a page that follows the reader's light / dark setting: a dark band above and below light content.
- ⚠️ Updating the shell is a PR here (`kit.mjs sync --python`); until it is merged the weekly drift check reports this repository as behind.

## Open questions

- **A policy for the shared shell (proposal, not implemented).** "A site of the owner's Pages set carries the current `site-kit` version" is a declared relationship with a named authority (`koydas/koydas` `site-kit/KIT.json`), which fits the coherence model (ADR-0002, ADR-0003) better than a workflow in another repository. It would be a new policy and therefore a new milestone (M4 or later); nothing in this ADR implements it.
- Should the content of the dashboards go dark as well, so the shell and the page share one theme? Not decided here; it would change every colour of the three dashboards.
