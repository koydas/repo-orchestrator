# M3: limitations

What M3 does not do, and what remains risky. Statements about the live model are **not measured**: no live call was possible when M3 was built (see [evaluation](evaluation.md#not-measured)).

## Scope

- **`scan` only.** `analyze-pr` (W2) has no investigation: a verdict delta by claim fingerprint and a base-side investigation need their own decision (ADR-0013 left it open; owner decision at the M3 gate). A reasoning claim is therefore never `introduced` or `resolved` by a pull request.
- **One declared claim (H2) and two intent reviews (H1).** The profile's "100+ ADRs" and "11 integration failure modes" are not declared. A claim nobody declared is never investigated: a semantic inconsistency no declaration selects is not found (recall is bounded by the declarations, [ADR-0004](../adr/0004-deterministic-checks-before-agentic-reasoning.md)).
- **Not-checkable outcomes** (for example P1's tests-count claim) are not routed to the Investigator: a model cannot count tests either. They stay `not_checkable_deterministically`.
- **No remediation (M4), no opportunities (M5), no GitHub write of any kind, no scheduled scans.**

## Verification

- A verified quote proves the text exists at the pinned place, not that the reasoning about it is right. Hence `needs_validation`, and a human for any claim without an entailment check.
- The only entailment kind is `numeric_relation`. Free-text claims (H2) can never be validated by code.
- A model that paraphrases instead of quoting yields `insufficient_evidence`. Quotes are compared against the real file but shown to the model with fence-like sequences neutralized, so a quote of a line containing `<<<` or `>>>` cannot verify: safe, but a recall cost.
- `dismissed` by a `consistent` proposal rests on verified quotes alone and is listed, not silent; it is the one place a proposal reduces a candidate without a check or a human (a new potential report line, never an existing finding).
- Injection detection is a list of patterns; a novel phrasing is not reported as an observation. It cannot change a state either way: that is the property tested.

## Operations

- **Cost and price table.** Cost is `tokens x list price` from a constant dated 2026-10-06; it is an estimate, and the table must be re-verified. The caps are conservative guesses, **not tuned on measurements**.
- **Real model behaviour is unmeasured**: malformed-output rate, `insufficient_evidence` rate, latency, whether the model quotes verbatim, whether `medium` effort suffices. The scripted Investigator proves the machinery, not the model ([S0 results](../../prototypes/langgraph-spike/docs/results.md#remaining-architectural-risks) said the same).
- **LangGraph.** 42 transitive packages and about 1 s of import time, paid only on `--investigate`; pinned; behaviours pinned by `tests/test_inv_framework.py`. Checkpoint schema stability across LangGraph versions, the default `async` durability under a hard kill (`sync` is always used) and concurrent writers from two processes are **not tested**.
- **Operator access** to the SQLite files bypasses every guard (documented in the [README](README.md#operator-notes)).
- **Recordings** contain quoted repository content and the model's answers. For private repositories (out of scope today, Q6) they would inherit the repository's confidentiality; retention is an open question ([ADR-0006](../adr/0006-evidence-provenance-uncertainty-and-reproducibility.md)).
- **A recording is valid for one code version.** A change to a prompt, the tool protocol or a pinned fixture invalidates it (`replay_miss`); the committed one is regenerated by `tests/tools/record_investigation.py`, and a test fails loudly when it is stale.
- **Rebuilding on resume needs the cache.** A resumed run reads the snapshots offline from the cache directory it recorded; a cleared cache gives `snapshot_changed`/`not_cached_offline`, never a re-pin.
