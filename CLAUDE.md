# CLAUDE.md — repo-orchestrator

Cross-repository coherence for independent GitHub repositories. **M1 (deterministic baseline), M2 (PR impact analysis) and M3 (bounded investigation) are implemented; M4–M5 are design only. Code exists in two places only: the M1–M3 package and the throwaway S0 spike (below).** Start with `README.md`, then `docs/architecture.md` and `docs/adr/README.md`.

## Rules

- **Only M1, M2 and M3 are implemented.** README and docs describe M1, M2 and M3 as implemented, and M4–M5 as "intended" or "proposed". Never describe a later milestone's capability as working.
- **M3 is authorized** ([MVP](docs/mvp.md), [M3 docs](docs/m3/README.md), [ADR-0014](docs/adr/0014-m3-llm-boundary-budgets-and-replay.md), [ADR-0015](docs/adr/0015-m3-reasoning-verification-and-validation.md), [ADR-0016](docs/adr/0016-m3-investigation-state-and-langgraph-confinement.md), all Proposed): C5 Investigator, P7 and W3 (bounded investigation), in the package `src/repo_orchestrator/investigation/` only. LangGraph is authorized in **one** module of it (`investigation/workflow.py`, the owner chose it at the M3 gate; ADR-0005 stays Proposed). Scope: `scan --investigate` only (opt-in; `analyze-pr` is not extended), reasoning candidates from P7 and from declared intent reviews, read-only tools over pinned snapshots, code-side quote verification, entailment checks, human decisions in a separate store namespace. Constraints that stay in force:
  - **exactly one component calls an LLM: C5** (`investigation/provider.py` is the only module that may open a network connection to a model provider). Every M1 and M2 code path stays LLM-free, framework-free and LangGraph-free, and `tests/test_architecture_constraints.py` enforces who may import what. The default `scan` and `analyze-pr` behaviour, reports, exit codes and run store are byte-identical with and without M3 present;
  - **the LLM proposes, code decides**: no numeric confidence; a quote is `verified` only if it exists verbatim at its pinned (repo, SHA, path, lines) with the recorded hash; a verified quote never confirms a claim; `confirmed` needs `validated_by_check` or `validated_by_human`; a `breaks` claim without an entailment check goes to a human; `insufficient_evidence` is never a pass;
  - **budgets are code constants** (`investigation/budgets.py`), authoritative in a ledger outside the graph state; repository text reaches prompts fenced as labelled data and instruction-like text is an observation, never followed;
  - the API key is read from `ANTHROPIC_API_KEY` once, never logged, stored, fixtured or reported; CI never calls a live model (offline replay of recorded responses; the live check is a manual `workflow_dispatch` step);
  - human decisions (W4) live in `inv_*` tables, a separate namespace: `findings`, `finding_events` and `pr_*` are never read or written by M3;
  - everything listed under M1 and M2 below that is not about the LLM (GET only, no GitHub write of any kind, analyzed content is data, declared relationships only, fixtures are history).
- **M2 is authorized** ([MVP](docs/mvp.md), [M2 docs](docs/m2/README.md), [ADR-0013](docs/adr/0013-m2-pr-impact-contracts.md) Proposed): C4 impact analyzer and W2 PR analysis, in the same package and CI. Scope: one pull request of one declared repository, read-only (`GET pulls/{n}`, `GET pulls/{n}/files`, plus the M1 endpoints), base and head snapshots, impact classification by relationship type, `introduced` / `pre-existing` / `resolved` / `undetermined` delta by fingerprint, Markdown and JSON PR report, a separate run kind in the SQLite store, `repo-orchestrator analyze-pr`. Constraints that stay in force:
  - everything listed under M1 below (deterministic only, no LLM outside C5, no agent framework, GET only, analyzed content is data, declared relationships only, fixtures are history);
  - **a pre-existing finding never fails a PR gate by itself**; `cannot_evaluate` on either side is an `undetermined` delta and makes the run incomplete (exit 2), never `introduced`, `resolved` or a pass; a missing base, head or changed-file list is incomplete, never a pass;
  - **no GitHub write of any kind**: no PR comment, no review, no status check, no issue, no PR creation. The token needs `contents: read` and `pull_requests: read` only;
  - a PR analysis never writes to the baseline-scan finding history (`findings`, `finding_events`).
- **M1 is authorized** ([MVP](docs/mvp.md), [M1 docs](docs/m1/README.md)): production code in `src/repo_orchestrator/`, declarations in `declarations/`, tests in `tests/`, CI in `.github/workflows/m1.yml` (which also runs the M2 checks). Scope: C1 collector, C2 declared relationship graph, C3 policy engine with P1–P6, W1 baseline scan, Markdown/JSON report, SQLite run store, CLI, static report dashboard (`dashboard.py`, [ADR-0012](docs/adr/0012-static-report-dashboard.md)). Constraints that stay in force:
  - deterministic checks only: **no LLM call, no agent framework, no LangGraph** in M1 and M2 code (everything outside `src/repo_orchestrator/investigation/`), and no import of the S0 spike or of its dependencies (`tests/test_architecture_constraints.py` enforces it);
  - the dashboard is a **read-only projection of `report.json`**: no scan execution, no recomputation of statuses, counts or order, no service, no script or dependency; only `models` and `report` are imported (`tests/test_dashboard.py` enforces it);
  - **read-only** toward every analyzed repository: GET requests only, no token with a write scope, analyzed content is data and is never executed or imported;
  - **declared relationships only**: observed or inferred relationships are reported, never evaluated; no automatic discovery;
  - **no policy, no finding**; an unresolved owner decision (Q1–Q6) is reported as a question, never decided by code;
  - `tests/fixtures/baseline/` is history: never edited to make a test pass; a correction needs evidence from the pinned revision, in the same PR.
- **Not authorized yet:** C6 remediation plans (M4), an Investigator inside `analyze-pr` (W2), an LLM call outside the Investigator module, optimization opportunities (M5), scheduled scans (the dashboard workflow is manual), PR comments, review or status-check writes, issue or PR creation outside this repository, any other GitHub write. Each needs its milestone and, for any write, its own ADR.
- **The S0 spike remains isolated**, `prototypes/langgraph-spike/` ([ADR-0005](docs/adr/0005-langgraph-for-investigation-workflows-only.md) §5). It is throwaway code that validates the LangGraph runtime on synthetic data. It authorizes no GitHub access and no LLM call; nothing outside `prototypes/langgraph-spike/` and its workflow (`.github/workflows/spike-langgraph.yml`) may import it or depend on it, and neither M1, M2 nor M3 does (the production graph in `investigation/workflow.py` is new code that reuses the S0 *design*, not S0 files). Describe it as "S0 spike: validated/not validated", never as a product capability. Its recommendation stays a proposal until the owner decides on ADR-0005.
- **ADRs stay `Proposed`** until the owner accepts them explicitly. Never change a status on your own. An accepted ADR is superseded, never edited.
- **Evidence over assertion.** A claim about another repository cites `repo path:line` at a pinned revision, or is labelled HYPOTHESIS (`docs/research/ecosystem-baseline.md` → How to read this page).
- **Coherence is not uniformity.** Never propose aligning a repository with the others without a policy and an authority (`docs/coherence-model.md`, ADR-0003, ADR-0009).
- **Read-only toward other repositories.** No issue, PR, comment or push elsewhere without the owner's explicit request (ADR-0007).
- **Mermaid diagrams match the text.** Changing a component, state or milestone means updating every diagram that shows it.
- Canonical names: components C1–C7 (`docs/architecture.md`), policies P1–P7 (`docs/coherence-model.md`), milestones S0, M1–M5 (`docs/mvp.md`), baseline ids R/D/C/N/H/U/Q (`docs/research/ecosystem-baseline.md`). Reuse them; do not invent parallel names.

Local checks before a push (the CI runs the same): `pip install -e '.[dev]'`, then `ruff check src tests && ruff format --check src tests && mypy && pytest`. Procedures in `.claude/skills/`: `new-adr`.
